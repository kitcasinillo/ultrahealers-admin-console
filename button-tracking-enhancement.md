Role: UX Copywriter & Digital Analytics Specialist

Task: Rename a set of generic button labels so that button click events are easily identifiable, contextual, and actionable in analytics tools (like Google Analytics, Mixpanel, or Amplitude).

Context: Currently, our event tracking reports vague button names like "Primary Action Button" or "Button Action," making it impossible to know which specific feature, page, or modal users are interacting with.

Naming Convention Rules:
1. Follow the format: [Page/Section]_[Action/Verb]_[Object/Context] (e.g., `pricing_subscribe_monthly`, `nav_login_submit`, `checkout_apply_coupon`).
2. Use lowercase with snake_case (or kebab-case) for event/label names, but also provide a human-readable display label if needed.
3. Keep names specific: Include the location or purpose so identical buttons (e.g., "Submit" or "Buy Now") on different pages can be distinguished.
4. Avoid generic terms like "Click Here", "Button Action", "Primary Action", or "Link".

Input List of Buttons / UI Elements to Rename:
- [Insert Page/Screen Name]: [Current Label / Generic Name / What it does]
- [Insert Page/Screen Name]: [Current Label / Generic Name / What it does]
- [Insert Page/Screen Name]: [Current Label / Generic Name / What it does]

Output Required:
Provide a table with 4 columns:
1. Current Generic Name / Location
2. Standardized Analytics Event/Element ID (e.g., `homepage_hero_cta_signup`)
3. Recommended UI Display Text (e.g., "Start Free Trial")
4. Reasoning / Context captured
